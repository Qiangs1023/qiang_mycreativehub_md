最近很多人在聊同一件事：一个人能不能带一支 Agent 团队，把选题、写作、发文整条链路跑起来。

我自己也在试。站点部署在 Cloudflare Pages，文章就是仓库里的 Markdown。技术上说，从「扫到热点」到「推上 main」，中间几乎没有硬障碍。

正因为障碍少，我反而更谨慎。

能自动写，不等于该自动发。

---

## 为什么现在特别容易想「全自动」

2026 年，独立创业的人明显变多了。Stripe 在 2026 年 5 月披露，当年第二季度截至当时，通过 Atlas 成立的 C 公司里，约 63% 是单人创始人。工具变强了，一个人能扛的事也变多了。

写作用 Agent 很诱人：它能半夜扫行业动态，第二天早上给你几篇成稿。GitHub 上 Agent Skills 也在快速「工程化」——不再只是一堆提示词，而是带触发条件、验证步骤和交接说明的工作流。像 Superpowers 这类项目，强调的是先澄清需求、再写计划、再实现和审查，而不是一上来就狂写。

另一方面，社区里最近也在强调：真正拉开差距的，往往不是再换一个更强的模型，而是给 Agent 配好 harness——上下文怎么管、结果怎么验、状态怎么接。Addy Osmani 等人把这套思路讲得很直白：模型负责推理，harness 负责让结果可复查。

这些都对。

但我越用越清楚：吞吐变大之后，瓶颈会从「写得出来吗」挪到「该不该发出去」。一人公司尤其如此——产能上去了，判断力如果跟不上，公开内容就会先出问题。

---

## 第一道门：只读热点，不直接定调

我让 Agent 做的第一件事，是搜和本站定位相关的信号：独立开发、个人站点、AI 工具落地、产品设计里那些不焦虑的做法。

它交回来的是线索，不是标题。

线索可以很多；定调必须是我。

原因很简单。Agent 擅长把「最近在聊什么」汇总成条；它不擅长判断「这件事值不值得出现在数字旷野」。后者要看我自己最近在想什么、读者是谁、以及这条内容会不会只是在追热度。

Dan Koe 最近也提醒过创作者：内容越容易生产，注意力反而越珍贵。对我来说，翻译过来就是——热点可以当原料，不能当选题本身。

所以第一道门的规则是：Agent 可以给我候选话题和出处链接，但最终选题由我点头。没有选题确认，不进入写作。

---

## 第二道门：可以成稿，但默认是 draft

成稿阶段，我愿意放权。

语气、结构、小标题，Agent 可以按站点已有文章的味道来写。我要求它：第一人称、少喊口号、事实轻引用、不要发明数据。写完之后，文件状态必须是 `status: draft`。

这一步对应一个更普遍的原则。OWASP 在 LLM 应用风险里把「过度自主」单独列出来，建议对高影响动作保留人工批准。对独立开发者来说，落到写作流水线上，就是一句话：先出稿，不发送。

Anthropic 自己做过 Project Vend：让模型打理一间小卖部大约一个月。结果包括虚构收款账户、亏本售卖、被说服乱发折扣。边界实验室都会在公开复盘里说「不会雇它」——我更没理由把「直接发布到主站」当成默认权限。

所以第二道门很硬：Agent 可以创建或修改草稿文件；它不能把 `draft` 改成 `published`，也不能自己合并到会触发上线的分支。权限尽量窄：读仓库、写草稿可以；推主分支、改生产配置，先关掉。

---

## 第三道门：发布前只做三件事

到了这一步，活很短，但必须是我做：

1. **读一遍声音**。有没有变成通用鸡汤？有没有堆感叹号和空口号？是不是还像我在说话？
2. **核对事实**。文中每一个数字、时间、产品名，我要能点开对应来源。打不开的，删掉或改成「据某篇文章」。
3. **问一个私人问题**：这篇发出去，是在帮读者想清楚一件事，还是只是证明我也能追热点？

三件事都过，我再改 frontmatter、提交，让 Cloudflare Pages 构建。

有人会觉得这太慢。我的体会相反：前面交给 Agent 之后，我每天真正花在发布上的时间变少了；变少的前提，是最后这三分钟没有被省略。

Jason Chuang 写过自己的运营 Agent 体系：发布锁住，改一个字符就要重新批准。我还没做到那么严，但方向一致——自动化可以扩大产能，不该扩大误伤半径。

---

## 先跑通「半自动」，再谈全自动

如果把流水线画成三格，我现在停在第二格和第三格之间：

- 选题：Agent 提案，我确认
- 写作：Agent 出稿，状态固定为 draft
- 发布：我批准，再推仓库

等草稿质量稳定几周，再考虑「定时开 PR」。等 PR 也稳了，再考虑极少数低风险内容的自动合并。一步一步加权限，比一上来全开安全得多。

独立开发最怕的，不是工具不够强，而是系统在你睡觉时替你做了一个不可逆的决定。

网站是长期资产。一篇写偏了的文章，可以改；一篇带着错误事实、用你的语气公开发布的文章，会先消耗信任。信任掉得快，攒得慢——这和「不焦虑地长期做事」是同一件事。

所以我给写作 Agent 的边界很清楚：

**你可以帮我找、帮我写、帮我整理。发布权，先留在我手里。**
