最近我总能刷到同一类演示：把简历丢给一组 Agent，或者对编程助手说一句「给我建个个人站」，过一会儿就能拿到一个像样的链接。项目墙整齐，配色也不像模板站那么一眼假。

壳的生产速度，已经快到让人怀疑：自己还对着 Markdown 改来改去，是不是有点迂。

我想了想，答案刚好相反。正因为壳不再稀缺，数字旷野更需要守住那些不能被流水线一并带走的东西——可复查的文本、还像我的人声，以及发布这件事本身。

---

## 个人站的壳，已经可以极快长出来

2026 年 8 月 4 日，Michael Tromba 写了自己正在做的 [Cactal](https://mike.gg/cactal)。它是一套面向 Agent 的建站平台：通过 MCP 接入之后，Agent 能建页面、往真正的内容系统里写稿、上传资源、连接域名、看数据、发布和回滚。他的判断很直接——模型会设计网页这件事，只会越来越强，设计很快不再是瓶颈；真正卡住的，是让 Agent 把做出来的东西发布出去、并持续运营的基础设施。

为了让「Agent 能发布」不等于「Agent 能把站弄坏」，Cactal 给每一行要上线的代码设了九道质量门，从格式、lint，一直到发布前把每一页都渲染一遍。他还提到，自己有一座站已经完全自动驾驶：每天自己调研、写作、发布，几乎不用他上手。

另一边，黄一航的 [PowerMyWeb](https://imyihang.com/en/projects/powermyweb) 已经上线，提供 Free 和 Pro。上传简历之后，八个分工明确的 Agent 会接力完成背景理解、风格探索、前端生成，再一键发到独立子域名；后面的修改也可以继续用对话完成。它特别针对「看起来都一样」做了反同质化采样。黄一航自己有句话说得很清楚：你正在看的这个站点，是他一行一行手写的；下一座，交给 AI 来写。

开源方向也在靠近这件事。Persona 给编程 Agent 一套从空白画布长出作品集的上下文和护栏；launchfolio 让 Agent 填一份配置、校验，再部署；像 cuttlefish 这类 agentic 静态站点生成器，则默认由人写内容、由 Agent 改外观和版式。中文创作者这边，也出现了把写作做成生产线的 Skill 栈，比如 Jacky Content OS，从定位、选题、结构到成稿和复盘，都按阶段排好。

这些工具并不互相替代。它们一起说明：搭出一座「看起来像站」的壳，已经不再是独立开发者最稀缺的能力。

## 我不怕 Agent 建站，我怕主编被一起外包

数字旷野对我来说，不只是一份在线简历，也不只是一组项目卡片。

它是一块我长期说话的地方。每两周一篇，写独立工作、产品设计，以及怎样在不焦虑的前提下过日子。读者如果点进来，大概不是来检查我有没有用上最新的建站流水线，而是看我有没有把一件事想清楚。

壳可以请人代建，想清楚不能代签。

Agent 很擅长生产「像那么回事」的结构：一段自我介绍、一排项目、再配一套不容易撞车的视觉方向。PowerMyWeb 要对付的，正是模板站长得太像、通用模型又容易写出同一张脸。这是真问题，他们的工程也确实对着这个问题去了。

我担心的是再往下一层。当「像你」也能被采样出来，页面上每个词都通顺，读完却不一定像我在说话。如果内容和发布再一并交给自动流程，个人站就不再是我维护的资产，而变成一套持续用我的名字往外发文字的装置。

Tromba 提到自己有一座站完全自动驾驶，我并不觉得那是坏事。对实验性站点，这很迷人。只是数字旷野不是那一类地方。我可以接受 Agent 帮我搭页面、整理草稿、提出改版方向；我不能接受它在我还没读过的时候，就把一篇东西推到网上。

所以界限其实很清楚：反对的不是 Agent 建站，而是把主编判断一起交出去。

## 所以我还是会打开那些 Markdown

数字旷野眼下的做法很朴素。文章以 Markdown 的形式放在仓库里，站点由 Cloudflare Pages 从仓库构建。文件就在那儿，我可以一行一行读完，也可以在 diff 里看见改了哪一句。

这不是怀旧，是为了让资产可复查。

哪天换主题、换生成器、甚至换一批帮忙的 Agent，源文件仍然是我能打开的文本。页面是渲染结果，仓库里的 Markdown 才是主资产。发布则是一次我知情的动作：稿子默认停在草稿，我打开文件读一遍，改掉不像自己的句子，核对过能点开的出处，才会让它进入会公开的流程。我没有在这里宣布新的自动上线，只是把这道发布权继续留在人这边。

Cactal 自己的营销站，Tromba 也写到一个细节：他让 Claude 去改，一分钟后草稿在等他批准。把发布基础设施做到这种程度的人，也没有把自己所有站点的放行权都交出去。这个细节比全自动更让我安心。

Content OS 和写作 Skill 栈的价值，我也看得懂。它们适合把素材、结构和复盘累积下来，避免每次都从零聊天。可如果把「生产线」理解成「自动出站、自动发文」，效率会先吃掉判断。生产线可以帮我准备材料；这篇东西该不该出现在数字旷野，还是得我点头。

有人会问：既然 Agent 已经能代建，为什么不把整站迁到更新的流水线上？我的理由很具体。脚手架、样式探索、第一版文案，都可以借力；源文件最好仍是我能对比、能回滚、能在普通编辑器里读完的 Markdown。Cloudflare Pages 只是把仓库变成站点的一层。真正要保护的，是那些我还认识的句子，以及「何时公开」这件事。

省下来的时间，我更愿意拿去读那篇即将用我的名字发出去的稿子。

个人站长期还站得住的部分，往往不是它上线有多快，而是几年后你回看，仍能认出那是自己的声音，并且知道每一篇是经过谁点头才出现的。

Markdown 还在手里，这件事对我就足够清楚。
