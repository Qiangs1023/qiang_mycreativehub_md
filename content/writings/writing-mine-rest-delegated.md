这两天的博客圈挺有意思。两位我一直在看的作者，前后脚公开了自己站点的幕后流水线。

### 一位是 Meow Apps 的作者。

他的旅行站 Offbeat Japan 有三种语言、七百多篇文章、每月七万多读者。他只写法语原文——英文版和日文版由 Agent 翻译，配图、画廊、SEO 检查、插件清理，全部通过 MCP 交给终端里的 Claude Code。十二个月，月访问量从一万三涨到七万三。他有一句很朴素的总结：每一篇文章都是我自己写的，文章以外的一切都交给 Agent。

### 另一位是 Marco Fabbri。

他的旅行站 StayByCity 走的是另一个极端：一个定时任务每晚九点开工，写八篇美食文章，每篇被读三遍、对照来源核验，再以 pull request 的形式合并上线。到早上页面就活了，全程没人碰过。他管这叫「活的网站」。



两个人的方向几乎是反的：一个把写作以外的所有事都交了出去，一个连写作本身都交了出去。但我不觉得这是保守与激进的区别——他们只是把线划在了不同的地方。

Meow 划的线在「笔迹」上。攻略里哪些店值得去、怎么描述一条徒步路线，这是他的署名；翻译和排版不是。所以他的站一年翻了五倍，他照样每天用法语写。

Marco 划的线在「事实」上。旅行站的内容是可核验的：营业时间、季节、票价，错了会被发现。所以他给每篇文章配了三轮校对，把风险外包给了流程。文风反而是次要的——没有人为了文风去查一个博物馆的开门时间。

看明白这两条线，我对自己这个小站的做法也踏实了一些。数字旷野现在也有一条流水线：选题扫描、封面、备份都是自动的，但每一篇随笔的第一稿还是我自己敲的。以前偶尔会怀疑这样是不是效率太低，是不是该让 Agent 直接出初稿我来改。现在想清楚了：判断标准不是「AI 能不能做」，而是「做错了会不会被发现，发现了我介不介意」。

翻译错了，读者看得出来，但可以改，我不太介意。SEO 描述写得平庸，没人在意，我不介意。可一篇随笔的味道不对——措辞、节奏、举的例子——我自己会介意，读者也会感觉到。这就是我的线：带着个人判断和笔迹的部分留下，可核验、可替换、可重跑的部分交出去。

这条线也不是一次划定的。Marco 的题材交得出去，是因为内容本身是事实；换成写教育观察，他的线大概也得往回收。同一个人，换个题材，线就会移动。所以真正值得定期问的不是「我还能再自动化掉什么」，而是「现在留在我手上的这段，还是不是我愿意署名的东西」。

想清楚这个，就不会被「全自动内容工厂」的故事推着跑了。那条流水线确实在运转，也确实在涨流量，但它生产的和我想写的东西，不是同一件。把可外包的部分痛快点交出去，才有底气把剩下的这段写得慢一点。
